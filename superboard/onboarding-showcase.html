A card is just a to-do until you use it. ▶ Agent runs the selected CLI in auto mode with the access and MCP/provider configuration that CLI already has — and it always reads the whole thread first, not just the last line.

The next ▶ Agent run normally continues that provider session. A warm prompt cache can reduce repeated processing; a cold cache loses no board data — it's a speed detail, not a memory one.

Why cut a thread

✂ New thread keeps the written history on the card but makes the next run start with a fresh session. Use it when the outcome changes or old context has become baggage — not after every reply.

When the agent needs an interactive login or a terminal-only action, ask it for the exact handoff command. Superboard does not add a second approval system around your agent CLI.
